# INCIDENTS Prototype 0.1

## 起動
`index.html` をブラウザ（Chrome / Edge 推奨）で開くだけ。インターネット・サーバー不要。

## 操作
1. 「調査を始める」→ オフィスで 業務日誌 / 端末 / 書棚 をクリック
2. 問題だと思う行を**長押し**して報告（約0.9秒。キーボードはEnter/Space長押し）
3. 正しければ「報告済み」。違えば「該当なし」（誤報告+1、再報告不可）
4. 全ての問題箇所をマークし、余計な指摘がなければ「特定」

## スコア（暫定）
S = max(0, 100 + 50×(誤指摘0なら1) − 2×秒 − 20×誤指摘数)。同じ誤指摘は1回だけ数える。

## 構成
- index.html / style.css / app.js : 本体
- cases.js : 事件データ（file:// でも読めるよう JSON ではなく JS 形式にしている）

## 事件4（現場調査）とスキップ
- `cases.js` の `type: "arg"` の事件が現場調査ステージ。通常UIが消え、発見数カウンターだけになる。
- 「スキップ」ボタンは2回押しで確定（誤操作防止）。スキップは0点で、最終結果に SKIP と表示。

## 事件2（新入社員・高橋のPC）
- 順序は cases.js の配列順（事件1 → 事件2 → 現場調査）。
- 調査対象は事件ごとに `spots` で定義。`delay`（秒）を付けると時間差で現れる（事件2のフィッシング通知は6秒後）。通知は画面を覆わず、操作は妨げない。
- 正解は5箇所（b1, w1, a2, m1, m3）。a1（急かす文言）は意図的に正解から除外し、解説で「ドメインの不一致が確認できる事実」と区別している。

## ローカル環境だけでスマホ確認（インターネット不要）
- ゲーム自体は外部通信を一切しない（外部フォント・CDN・解析なし）。
- PCで `start_server.bat`（Windows）をダブルクリック、または `python start_server.py`。表示されたURLをスマホで開く。
  - スマホはPCと同じWi-Fi、またはPCのモバイルホットスポットにつなぐ（インターネット接続は不要）。
  - `/#debug` を付けるとデバッグパネル付きで開く。修正は再読み込みで反映（キャッシュなし）。
  - 公開されるのはこのフォルダだけ。信頼できるネットワークでのみ使うこと。初回のファイアウォール確認は「プライベートネットワーク」のみ許可する。
- 実機のデバッグツール：Android（Chrome）はUSB接続＋PCの chrome://inspect、iPhoneはMacのSafariの開発メニュー。いずれもPCとスマホの間だけで完結する。
